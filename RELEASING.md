# Releasing

How `omnes_formae` is made installable from GitHub, from a dev PC,
with no CI and nothing beyond setuptools (or uv). v0.2.0 was the first
release made this way. The older `v0.1.0` tag predates packaging and has no
`pyproject.toml`, so it can't be installed.

## Why not GitHub Packages

GitHub Packages has registries for npm, Maven, Gradle, NuGet, RubyGems and
containers, but not for Python. There is no pip index to publish to, and none
is needed: pip installs from a URL.

## The plan

1. **`pyproject.toml`** in the repo root (done; it also sets `readme` and
   project URLs):

   ```toml
   [build-system]
   requires = ["setuptools>=77"]
   build-backend = "setuptools.build_meta"

   [project]
   name = "omnes-formae"
   version = "0.2.0"
   description = "Every inflected Latin form in Whitaker's Words, and a tagged lookup"
   requires-python = ">=3.10"
   license = "AGPL-3.0-or-later"

   [project.scripts]
   omnes-formae = "omnes_formae.__main__:main"

   [tool.setuptools]
   packages = ["omnes_formae"]

   [tool.setuptools.package-data]
   omnes_formae = ["data/whitaker/*", "data/bespoke/*"]
   ```

   setuptools 77 is the first to read `license` as an SPDX expression.
   `packages` has to be listed: the repo root also holds scripts and
   `submodules/`, which setuptools would otherwise try to package or reject.
   `package-data` is needed because the package reads its data files at run
   time, and setuptools leaves out non-`.py` files unless told. The code
   already finds them with `Path(__file__).parent / "data"`, so it works from
   an installed copy unchanged.

2. **Publish a version** by tagging and pushing:

   ```sh
   git tag v0.2.0
   git push origin v0.2.0
   ```

3. **Install from the tag's source zip:**

   ```sh
   pip install https://github.com/njg4ne/whitakers-words/archive/refs/tags/v0.2.0.zip
   uv pip install https://github.com/njg4ne/whitakers-words/archive/refs/tags/v0.2.0.zip
   uv add https://github.com/njg4ne/whitakers-words/archive/refs/tags/v0.2.0.zip
   ```

   pip builds the package on the user's machine from `pyproject.toml`. Users
   don't need Git, and the zip leaves out the submodules.

To release a new version: bump `version` in `pyproject.toml`, commit, tag, push.

## Why the zip, not `git+https://...`

`pip install "git+https://github.com/njg4ne/whitakers-words.git@v0.2.0"` also
works in principle, but pip initializes Git submodules when it installs from
a Git URL. Here that means cloning both Ada forks, and the mk270 one is
registered with an SSH URL (`git@github.com:...` in `.gitmodules`), which
fails for anyone without GitHub SSH keys. The zip avoids all of that. If
`git+` installs are wanted anyway, change that submodule URL to `https://`
first, and accept the extra download (including one from Bitbucket).

## Before the first release

- **Check it builds:** done once: `uv build` produced a wheel with
  `data/whitaker/` and `data/bespoke/`, and an sdist with no submodules. The
  wheel, installed in a fresh virtual environment, passed
  `python -m omnes_formae.verify`, and `omnes-formae` wrote
  the full list. `uv build` leaves `build/` and `*.egg-info/` in the repo;
  both are in `.gitignore`.
- **The repo must be public** for those URLs to work without a login.
- **Licence:** the code is under the GNU AGPL v3 or later (`LICENSE`).
  Whitaker's data is covered by `omnes_formae/data/whitaker/LICENCE.txt`,
  which ships with the package.

## The docs site

`docs/` is a [docsify](https://docsify.js.org) site: `docs/index.html` loads
docsify from jsDelivr and renders the Markdown files in the browser, so there
is no build step and nothing to install. `docs/.nojekyll` stops GitHub Pages
running Jekyll over the folder. To publish it, in the repo's Settings →
Pages, set the source to "Deploy from a branch", branch `main`, folder
`/docs`. It is then served at <https://njg4ne.github.io/whitakers-words/>,
the URL that `README.md` and `pyproject.toml` already give.

`docs/api.md` and `docs/limitations.md` are generated by `build_docs.py`;
run it before tagging so they match the code (`--check` reports whether they
do).

## Fallback: a wheel on a GitHub Release

If building on the user's machine is ever a problem, run `uv build` locally
and attach `dist/omnes_formae-0.2.0-py3-none-any.whl` to the v0.2.0
release in GitHub's web UI. Users then install that file's download URL with
pip. This adds a manual upload to each release, so start with the zip.
